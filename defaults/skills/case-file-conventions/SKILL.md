# 案件文件分夹与命名规范

## 目录结构

每个案件目录下固定包含以下文件夹：

```
案件名/
├── 材料/        ← 外部来源、案件原始材料
├── 文书/        ← 对外交付的法律文件
├── 分析/        ← 内部研究（非交付物）
├── 任务/
├── 日程/
├── 期限/
├── 大事记/
└── 案件名.md    ← 案件主文件（frontmatter + 正文）
```

任务、日程、期限使用 `ops/cases/` 下的通用 base：

- `ops/cases/任务.base`
- `ops/cases/日程.base`
- `ops/cases/期限.base`

新建案件时，`任务/`、`日程/`、`期限/` 目录只放事项文件。案件主文件嵌入上述三个通用 base，通用 base 通过 `关联项目` 与当前案卷主文件关联。

## 三个文件夹的边界

### 材料/

**存什么**：案件原始材料、外部来源。
- 法院文书（裁定书、传票、判决书等）
- 对方提交的材料（答辩状、证据等）
- 客户提供的材料（合同、沟通记录等）
- 庭审记录、谈话记录等原始记录
- 财产保全清单等事实性汇总

**命名规则**：正常命名，能够区分案件即可。推荐包含案件简称、材料类型、日期或来源关键信息。

**frontmatter 示例**：
```yaml
认知层: 外部来源
```

### 文书/

**存什么**：对外交付的法律文件，不论由谁起草。
- 起诉状、答辩状、代理意见
- 各类申请书（保全、续冻、追加被告等）
- 证据清单
- 法律服务合同
- 催告函、律师函

**命名规则**：正常命名，能够区分案件即可。推荐包含案件简称、文件类型和日期。

**frontmatter 必填字段**：
```yaml
认知层: AI产出 | 人机共创 | 人类记录
```

### 分析/

**存什么**：内部研究分析，不直接对外交付。
- 类案检索报告
- 法律适用分析
- 案情分析备忘录
- 策略分析

**命名规则**：正常命名，能够区分案件即可。推荐包含案件简称、分析主题和日期。

**frontmatter 示例**：
```yaml
认知层: AI产出
```

## 认知层标签体系

用于 `文书/` 和 `分析/` 中的所有文件，标识产出者：

| 认知层值 | 含义 | 变更时机 |
|---------|------|---------|
| `AI产出` | AI 生成的初稿，未经人类修改 | AI 生成时自动标注 |
| `人机共创` | AI 初稿经人类修改后的定稿 | 人类修改后更新 |
| `人类记录` | 人类自己从头写的 | 创建时标注 |

**工作流**：
1. AI 生成文书 → 标注 `认知层: AI产出`
2. 人类在 AI 基础上修改 → 更新为 `认知层: 人机共创`
3. 人类自己写的 → 标注 `认知层: 人类记录`

## 文件命名规范

### 文件名格式

```
{案件简称}-{文件类型或材料类型}-{日期}.{ext}
```

**示例**：
- `珠海永通vs郑贤广-庭审记录-2026-04-21.md`
- `珠海永通vs郑贤广-财产保全清单-2026-04-21.md`
- `珠海永通vs郑贤广-续行冻结申请书-2026-04-21.md`
- `珠海永通vs郑贤广-类案检索报告-2026-04-16.md`

文件名目标是让人在目录里一眼看出案件、文件类型和时间。无需使用固定前缀。

### DOCX 同名同目录

文书的 MD 和 DOCX 版本存放在同一文件夹（`文书/`），使用相同文件名不同扩展名。


## 案件主文件（案件名.md）结构规范

### frontmatter：只放静态案件信息

frontmatter 只存放案件基本属性，这些字段在案件生命周期内极少变动：

```yaml
---
性质: 工作
案件类型: 诉讼 | 仲裁 | 常年法律顾问 | 非诉讼专项 | ...
案件状态: 进行中 | 归档 | 休眠
创建时间: YYYY-MM-DD
ims案号: ""
案号: ""
我方当事人: []
对方当事人: []
委托人: []
主办律师: []
代理阶段: []    # 如：一审、二审、执行
管辖机关: []
法官: []
客户联系人: ""
服务范围说明: ""
base: "[[案卷.base]]"
---
```

### 正文：放动态内容

以下内容 **不得** 放在 frontmatter，必须放在正文对应章节中，用 wiki-link 引用具体文件：

```markdown
## 相关任务
- [[任务/续封-招商银行账户]]
- [[ops/dashboard/近期日程/催客户支付律师费|催客户支付律师费]]

## 任务
![[ops/cases/任务.base|任务.base]]

## 日程
![[ops/cases/日程.base|日程.base]]

## 期限
![[ops/cases/期限.base|期限.base]]

## 大事记
- [[大事记/提交续行冻结申请书]]
- [[ops/cases/大事记/收到保全反馈和开庭传票|收到保全反馈和开庭传票]]

## 程序信息
- 案号、代理阶段、管辖机关、法官等信息写入案件主文件 frontmatter。

## 财产保全
- 保全申请、续封办理等工作写入 `任务/`。
- 保全期限、冻结到期等提醒写入 `期限/`。
- 保全立案、承办法官确定等节点写入 `大事记/`。
- 保全清单、保全文书等材料写入 `材料/` 或 `文书/`。
```

**原则**：frontmatter = 静态属性（改了就是案件本身变了）；正文 = 动态事项（任务、日程、事件会持续增减）。
## 注意事项

- `文书/` 和 `分析/` 的区别在于**是否对外交付**，而非由谁起草
- 所有对外交付的文件放 `文书/`，不论产出者是谁
- 纯研究性质、不提交给法院或对方的放 `分析/`
- 认知层标签反映的是**最终版本的产出方式**，不是初稿方式
- 如果一份分析后来变成对外交付的文书，应从 `分析/` 移到 `文书/`
