# Legal Case Init

> 法律案件快速初始化工具
>
> 自动创建标准化案件目录结构，预填充核心案件文件

## 何时使用

- **自动触发**：你说"新建案件""创建诉讼案件""XX vs XX案""新建顾问项目"时
- **手动调用**：`/legal-case-init`

## 前置检查

1. **既有案件和复用排除**：先以当事人、案由、争议焦点和拟交付文书在项目标准结构的 `ops/cases/案卷/`、`ops/cases/休眠案卷/`、`ops/cases/归档案卷/`、`ops/projects/` 中检索。确认不存在既有案件后，再查 `templates/` 是否已有可安全复用的模板或成熟结构；只有完成这两步，才创建新案件。
2. 如果项目配置了共享知识库，再在其中检索可迁移的判断资产或流程规则；没有配置时跳过。
3. **语音输入消歧**：检测案件名称中的易混淆词，例如同音公司名；如有歧义，向用户确认。
4. **案件名称确认**：
   ```
   我听到：[原告/客户] vs [被告/相对方]
   是否正确？如有误请更正。
   ```

## 执行流程

### Step 1: 收集案件信息

**必需信息**：
- 案件简称（如：兴众为vs奇目智方）
- 当事人/客户全称
- 案由或交易类型（如：买卖合同纠纷、股权收购、常年法律顾问）
- 管辖机关或审理法院（如已知）

**可选信息**：
- 对方当事人/相对方信息
- 案件背景（一句话概括）
- 标的金额
- 代理阶段或服务范围

### Step 2: 创建案件目录

Mju 会在项目标准结构下创建案件目录（诉讼进 `ops/cases/案卷/`，顾问/专项进 `ops/projects/活跃项目/`），并自动生成统一子目录：

```
{案件名}/
├── 任务/        ← 任务页
├── 期限/        ← 期限页
├── 日程/        ← 日程页
├── 材料/        ← 外部来源、案件原始材料
├── 分析/        ← 内部研究（非交付物）
├── 文书/        ← 对外交付的法律文件
├── 工作包/      ← 同一事项的多份产物
├── 大事记/      ← 已发生的重要节点
└── {案件名}.md  ← 案件主文件
```

> 文件分夹与命名详细规范见 `case-file-conventions` skill。

### Step 3: 创建/填充案件主文件

案件主文件为 `{案件名}.md`，位于案件目录根下。若文件已存在则读取并更新，不覆盖。填充以下 frontmatter：

```yaml
---
案件名: "{案件名}"
案件类型: 诉讼 | 仲裁 | 常年法律顾问 | 非诉讼专项
状态: 进行中
创建时间: YYYY-MM-DD
案号: ""
我方当事人: []
对方当事人: []
委托人: []
代理阶段: []
管辖机关: []
---
```

### Step 4: 预填充核心信息

在案件主文件正文中填充以下结构：

```markdown
# {案件名}

## 当事人与背景
（已收集信息写入此处；缺失项标注“待补充”）

## 程序阶段
（待补充）

## 待办事项
见 `任务/` 目录。

## 材料清单
见 `材料/` 目录。

## 关键期限
见 `期限/` 目录。

## 检索与复用

- 类似案卷/项目：
- 模板或既有文书：
- 判断资产/工作流：
- 采用边界与待核验点：
```

没有可靠命中时明确写“未发现可安全复用的材料”，不为凑内容而复制旧案观点。

### Step 5: 当事人/客户档案（如项目配置了资料库）

若项目配置了当事人/客户资料库目录，可在其中同步创建档案；否则仅在案件主文件中记录当事人信息，不强制创建额外资料库文件。

需要收集的信息：
- 企业：名称、住所地、统一社会信用代码、法定代表人
- 个人：姓名、住所地、公民身份号码、联系方式

### Step 6: 询问下一步

```
案件文件夹已创建：{路径}

是否需要同时完成以下任务：
- 起草法律服务合同/顾问协议
- 创建起诉状/答辩状/律师函
- 整理现有证据清单
- 启动案件工作流
```

## 命名规范

### 案件目录命名

```
{原告/客户简称}vs{被告/相对方简称}[-{补充说明}]
```

**示例**：
- `兴众为vs奇目智方/`
- `星之耀vs北京互航-一审/`
- `珠海永通合伙vs郑贤广/`

### 文件命名

遵循 `case-file-conventions` skill 的规范：
- 外部来源：`{案件简称}-{材料类型}-{日期}.md`
- 文书/分析：`{案件简称}-{文件类型}-{日期}.md`

## 协作技能

- `case-file-conventions` - 文件分夹、命名和案件状态治理
- `task-do` - 新案建立后的任务、日程和期限记录

## 注意事项

1. **主体准确性**：特别留意公司名称中的同音字差异（如恒业/横业）
2. **目录层级**：诉讼案件创建在 `ops/cases/案卷/` 下，顾问/专项创建在 `ops/projects/活跃项目/` 下
3. 不要手动维护目录结构；Mju 会自动生成标准骨架
4. 新建 skill 的存放位置：仓库的 `defaults/skills/` 用于内置 skill，项目运行时通过 `.agents/skills/` 桥接
