# Legal Case Init

> 争议解决案件快速初始化工具
>
> 自动创建标准化案件目录结构，预填充核心案件文件

## 何时使用

- **自动触发**：你说"新建争议解决案件""创建诉讼案件""XX vs XX案"时
- **手动调用**：`/legal-case-init`

## 前置检查

1. **既有案卷和复用排除**：先以当事人、案由、争议焦点和拟交付文书在 `ops/cases/案卷/`、`ops/cases/休眠案卷/`、`ops/cases/归档案卷/`、`ops/projects/` 中检索。确认不存在既有案卷后，再查 `templates/`、`config/templates/`、`wiki/distilled/`、`shared-memory/工作流/` 是否已有可安全复用的模板、判断资产或流程；只有完成这两步，才创建新案卷。

2. **语音输入消歧**：检测案件名称中的易混淆词
   - 恒业 / 横业
   - 话本 / 画本
   - 兴众为 / 星之耀
   - 任何可能同音的公司名

3. **案件名称确认**：
   ```
   我听到：[原告] vs [被告]
   是否正确？如有误请更正。
   ```

## 执行流程

### Step 1: 收集案件信息

**必需信息**：
- 案件简称（如：兴众为vs奇目智方）
- 原告全称 + 统一社会信用代码
- 被告全称 + 统一社会信用代码（如有）
- 案由（如：买卖合同纠纷、追加被执行人异议之诉）
- 审理法院

**可选信息**：
- 第三人信息
- 案件背景（一句话概括）
- 标的金额

### Step 2: 创建案件目录

在 Obsidian vault 的 `ops/cases/案卷/` 下创建案件目录，结构如下：

```
{案件名}/
├── 材料/        ← 外部来源、案件原始材料
├── 文书/        ← 对外交付的法律文件（必填 认知层）
├── 分析/        ← 内部研究（非交付物）
├── 任务/
├── 大事记/
├── 日程/
├── 期限/
└── {案件名}.md  ← 案件主文件（frontmatter 挂 base 模板）
```

同时创建索引文件 `材料.md`、`文书.md`、`分析.md`（用于 Obsidian 内链接汇总）。

> 文件分夹与命名详细规范见 `case-file-conventions` skill。

### Step 3: 创建案件主文件

使用 `案卷.base` 作为 frontmatter base 模板，填充已收集的案件信息。

### Step 4: 预填充核心信息

在案件主文件 `{案件名}.md` 中填充以下结构：

```yaml
---
base: "[[案卷.base]]"
性质: 工作
我方当事人:
  - "[[ops/cases/信息维护系统/案件资料库/委托人/{我方当事人名}|{我方当事人名}]]"
委托人:
  - "[[ops/cases/信息维护系统/案件资料库/委托人/{委托人名}|{委托人名}]]"
对方当事人:
  - "[[ops/cases/信息维护系统/案件资料库/对方当事人/{对方当事人名}|{对方当事人名}]]"
案件类型: 诉讼
主办律师:
  - 林雁
管辖机关:
  - "[[ops/cases/信息维护系统/案件资料库/管辖机关管理/{法院名}|{法院名}]]"
案件状态: 进行中
---
```

如果当事人不存在于 `ops/cases/信息维护系统/案件资料库/` 中，同步创建当事人档案。

### Step 5: 创建当事人档案（如不存在）

在以下位置分别创建：
- 我方或委托人：`ops/cases/信息维护系统/案件资料库/委托人/{当事人名}.md`
- 对方当事人：`ops/cases/信息维护系统/案件资料库/对方当事人/{当事人名}.md`

需要收集的信息：
- 企业：名称、住所地、统一社会信用代码、法定代表人
- 个人：姓名、住所地、公民身份号码、联系方式

### Step 6: 记录本次复用检索

在案件主文件或首个实质性任务页加入：

```markdown
## 检索与复用

- 类似案卷/项目：
- 模板或既有文书：
- 判断资产/工作流：
- 日记或 Get笔记（仅定向命中时）：
- 采用边界与待核验点：
```

没有可靠命中时明确写“未发现可安全复用的材料”，不为凑内容而复制旧案观点。

### Step 7: 询问下一步

```
案件文件夹已创建：{路径}

是否需要同时完成以下任务：
- 起草法律服务合同
- 创建起诉状/答辩状
- 整理现有证据清单
```

## 命名规范

### 案件目录命名

```
{原告简称}vs{被告简称}[-{补充说明}]
```

**示例**：
- `兴众为vs奇目智方/`
- `星之耀vs北京互航-一审/`
- `珠海永通合伙vs郑贤广/`

### 文件命名

遵循 `case-file-conventions` skill 的规范：
- 外部来源：`source-{描述}.md`
- 文书/分析：`process-{案件简称}-{文件类型}-{日期}.md`

## 协作技能

- `case-file-conventions` - 文件分夹、命名和案件状态治理
- `task-do` - 新案建立后的任务、日程和期限记录
- `case-analysis` - 事实、证据与争点的首轮分析
- `litigation-engagement-documents` - 需要诉讼委托手续时使用

## 注意事项

1. **主体准确性**：特别留意公司名称中的同音字差异（如恒业/横业、话本/画本）
2. **目录层级**：案件创建在 `ops/cases/案卷/` 下
3. **wikilink**：使用 Obsidian 格式的 wikilink 进行文件互链
4. **新建 skill 的存放位置**：Vault 的 `config/agents/skills/`；`.agents/skills` 仅作为运行时桥接路径。
