# Mju 使用指南

Mju 是一个本地优先的法律工作台。它把项目、案件、任务、会话、期限、日程和交付物放在同一条工作链上：先确定事项归属，再启动会话完成工作，最后把产出回收到案件中。

## 核心概念

- **项目**：一个工作根目录。诉讼、顾问和专项事务都在项目内管理。
- **案件**：项目内的具体事项，可分为诉讼、顾问或专项；无法归类的指令进入“通用任务”收件箱。
- **任务**：一项可执行工作，可绑定一个会话并在看板中跟踪。
- **会话**：与 Agent 的具体工作记录。一个任务可以持续使用其绑定会话。
- **期限与日程**：案件中的时间节点。Dates 页面只读展示已有记录，不提供手工新建期限的入口。
- **交付物**：面向客户或内部的可交付文件，可从 Markdown 生成 DOCX。
- **Vault**：Obsidian 项目中，案件材料和业务记录所在的实际目录。
- **内置子 Agent**：justice 负责法律分析，magician 负责文书起草，chariot 负责执行检索；可在 AGENTS 中查看、复制并按需要覆盖默认配置。

## 页面导览

### 首页 `/`

首页是工作入口：输入一句指令后，系统会给出案件识别提示；确认后创建或进入任务并启动会话。页面还提供项目初始化、近期在办事项、项目选择器和配置条。

### 案件看板 `/board/[caseId]`

看板按列管理任务状态。这里可以导入材料、启动工作流、查看交付物，也可以通过任务卡片菜单处理任务。

### Dates `/dates`

集中以列表、周和月三种视图展示项目已有的任务、期限和日程。这里用于查看和统筹，不直接新增时间节点。

### 任务详情 `/task/[taskId]`

左侧是与 Agent 的完整对话，右侧可预览工作文档。此处可导出会话、生成 DOCX、停止运行中的任务或改派工作。

## 配置入口

- **MODELS**：配置和选择模型、认证方式及默认模型。
- **SKILLS**：查看、启用或禁用当前可用 skills。
- **AGENTS**：查看和配置子 Agent；编辑内置 Agent 会创建你的用户级覆盖副本。
- **PLUGINS**：管理 Pi package 插件。
- **MINERU**：配置文档转换服务。
- **THEME**：切换浅色或深色外观。

## 常用工作流

### 一句话创建任务

在首页直接写明要做的事情和案件线索。确认案件识别后，Mju 会把任务与会话绑定，并让 Agent 在该案件目录中工作。

### 导入并整理材料

在案件看板导入 PDF、DOCX、PPT 或 XLS 等文件。MinerU 转换为 Markdown 后，系统会自动分析、归类并把文件归入相应位置，再生成需要复核的事项。原始非 Markdown 文件不会保留在案件 Vault 中。

### 使用内置工作流

案件看板可启动内置工作流，例如诉讼接案。先预览工作流，再启动执行；工作流运行记录会与案件保持关联。

### 生成 DOCX

完成 Markdown 文书后，在任务详情或交付物处选择模板生成 DOCX。生成前应先核对当事人、事实、金额和日期等业务信息。

## 命令行启动

安装后可用 `mju` 启动。常用参数包括：

- `--port <端口>`：指定端口。
- `--hostname <地址>`：指定监听地址。
- `--no-open`：启动后不自动打开浏览器。

如果不确定事项应放入哪个案件，先在首页描述事实和目标；系统无法匹配时会把它放进“通用任务”，之后可再整理归类。
